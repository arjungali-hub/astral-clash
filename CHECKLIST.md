# Astral Clash — Build Brief Checklist

Tracks every item from the build-brief prompt. Updated after every batch of changes to `index.html`.

**Time-scaling approach (Batch 1 decision):** using the `dt` multiplier model (dt = 1.0 at 60fps), not a full frames→seconds conversion. Existing per-frame tuning constants stay valid multiplied by `dt`, rather than rewriting every constant into real-world units.

## Regression found and fixed outside the batch list

**The game was completely unplayable after the previous update** — the fighter-select grids were empty and the Bot toggle button did nothing. Root cause: `onWindowResize()` was called immediately at setup time (to size the canvas on first load) but reads `camera`, which is a `const` declared *later* in the script — a temporal-dead-zone `ReferenceError` that threw before `buildGrid()` or the bot-toggle listener ever ran, silently halting the rest of the script. `node --check` never caught this because it only validates syntax, not runtime references — confirmed by actually executing the script under a mocked DOM/THREE harness. Fixed by moving the initial `onWindowResize()` call to after `camera` is constructed. This wasn't on the brief's list because it was introduced by the huge feature-update batch, not by anything the brief was written against — noting it here since it directly affects the "no console errors" verify item for every batch since.

**Special meter always showed NaN and never charged.** Root cause: `Fighter.meterRateMult` was read in two places (passive regen and on-hit meter gain, both part of Batch 4's unified meter-generation rework) but the constructor never actually assigned it from the character config — so it was `undefined`, `undefined * anything` is `NaN`, and once `specialMeter` went `NaN` it stayed `NaN` forever (any further arithmetic on a `NaN` is still `NaN`), which is exactly the "shows NaN and won't charge" symptom reported. This is a case the mock-DOM harness can't catch — `undefined * x` doesn't throw, it just silently produces `NaN`, so the script "ran fine" by the harness's own definition even with this bug present; it needed an actual human noticing wrong-looking output. Fixed by adding the missing `this.meterRateMult = cfg.meterRateMult;` in the constructor, alongside the other per-character stat assignments.

**Training mode removed at the user's explicit request** after being built in Batch 9 — see that batch's section below for what was deleted.

**Per-attack weapon animation added**, on request, beyond the whole-mesh lean Batch 8 shipped. Each character's mesh builder now stashes a `weapon` part (or parts — Voss's twin daggers move together) and a `weaponAnim` config; `initMesh()` captures each part's rest transform once, and a new `animateWeapon()` (called every frame from `render3D`, layered on top of the existing lean) drives a real per-character swing: Kaelen and Voss get a horizontal slash/stab arc (rotate around Y), Draven gets a heavy overhead swing (rotate around Z), Gorgonok gets a straight punch thrust (position offset along local X), and the two ranged casters (Lyra, Seraphine) get a charge-and-release scale pulse on their shard/halo instead of a melee swing, since they don't have a weapon part to swing. All three animation types share one generic startup→active→recovery progress curve (wind-up extreme → follow-through extreme → ease back to rest) rather than six bespoke per-character animation functions.

**The "skill" action (third attack, on top of basic/special) removed at the user's explicit request.** This was a bigger removal than it looks — every character had a unique skill (Kaelen's Twin Strike, Lyra's Glass Step, Gorgonok's Ground Pound, Voss's Smoke Step, Draven's Bulwark Stance, Seraphine's Radiant Pulse), so this touches most systems in the file: `CHARACTERS` config (`skill2Id`/`skill2Name`/`skill2Desc`/`skill2Cooldown` fields), `FRAME_DATA` (the `skill` startup/active/recovery sub-object per character), the whole `Fighter.doSkill()` method and its six-case switch, `tryStartAction`/`updateActionState`'s skill branches, `skill2Cooldown`/`skill2CooldownMax` fields and their per-frame tick, the HUD's skill-cooldown bar and "Skill Ready/Xs" label, the feet-level `skillReadyRing` ability pip, the fighter-detail panel's Skill ability row, key bindings (P1 `H`, P2 `;`, gamepad Y button) and their rebind-screen/controls-summary entries, bot AI's `skillChance`/skill-trigger logic in `BOT_DIFFICULTY`, and the skill wind-up sound-pitch case. One side effect worth flagging: Draven's Bulwark Stance was his *only* source of the shield/damage-reduction mechanic (`shieldFrames`), so removing it means Draven no longer has any damage-mitigation ability — his `shieldFrames`/`shieldRing`/`shieldReduction` infrastructure is still fully in place and still used by Seraphine's Astral Ward *special* (which independently grants a shield and was never a skill), just no longer reachable by Draven. Left his flavor text ("nearly unbreakable tank") as-is rather than rewriting character descriptions, which felt like scope beyond "remove skills."

**Passive HP regen ("healing over time") removed at the user's explicit request.** `cfg.regen` (a per-character passive-regen rate) and the `this.hp += this.regen * dt` tick that ran it every frame have both been deleted, along with the `regen:` field from all six `CHARACTERS` entries. This only ever restored a fraction of a percent of HP per frame passively — it did *not* touch the pickup heal (`PICKUP_HEAL_PCT`), Seraphine's Astral Ward special's one-shot heal-on-cast, or the now-removed Radiant Pulse skill (already gone from the skill removal above) — those are instant, on-cast/on-pickup heals, not "over time," and weren't asked to go.

**Projectiles passed straight through staircases.** Root cause: the projectile-collision check in `tickEffects()` only tested against `OBSTACLES` (pillars) and `PLATFORMS` (one-way floors, blocked only when the shot is below the platform's underside) — `TERRAIN` (steps/ramps) was never checked at all, so a low-flying shard/orb clipped straight through a stair's solid riser. Fixed by adding a third check: a projectile below a `step`-type terrain entry's height and within its `hw`/`hd` footprint is now blocked, same style as the existing platform check. Ramps are deliberately excluded — they're a smooth walkable incline with no vertical face to collide against, so "blocking" one would need slope-interpolated height math for a case that isn't really "a shot going through a wall" the way a stair riser is.

**Start screen (fighter-select menu) UI improved, on request.** The middle VS column had become a dumping ground for every menu-level setting added since Batch 9 (Rebind Keys, HUD Text scale, Audio Settings, stacked four-deep in a 110px column) — it competed with the actual P1-vs-P2 matchup for attention and made the "pick, pick, fight" flow harder to read at a glance. Changes: moved Rebind/HUD-scale/Audio into a new `.menu-footer` row (a muted, secondary-styled button strip below the whole select screen, visually separated by a top border) so the VS column only holds what's actually about the upcoming fight (VS label, status, bot difficulty). Each side panel's Bot-toggle/Random buttons moved from two stacked full-width buttons into one `.side-actions` row, saving vertical space. `#vs-status` gets a `.ready` state (bigger, cyan, gently pulsing via a CSS animation) toggled from `refreshMenuUI()` the instant both sides are confirmed, instead of the "Fight!" text just quietly changing color like every other status message. The `<h1>` title got a size/letter-spacing bump and a small gradient underline (`.brand-divider`) for a bit more visual presence instead of a single flat text-shadow line. Not visually verified in an actual browser — this is CSS/DOM structure only, checked for JS correctness (the `.ready` class toggle) via the usual syntax+mock-harness pass, not for how it actually looks.

**You could walk straight up any terrain, no matter how tall, without jumping — including onto Sundered Stair's tallest (54-unit) step from ground level.** Root cause: `groundLevelAt()` snaps a grounded fighter's `z` straight to whatever height is under their new feet every frame, with no limit on how big that jump in height could be — so sidestepping into the base of a tall step teleported you onto its top exactly the same way a gentle few-unit lip would. Fixed with a new `Fighter.resolveTallTerrain()`: while grounded, a move that would raise you more than `MAX_WALK_STEP_UP` (20 units) in one step now gets blocked like a wall instead of auto-climbed — tried as a full move, then X-only, then Y-only, then reverted entirely if none of those clear it (same axis-separated slide-along-the-wall approach `resolvePlatformWalls` already used for platforms). Sundered Stair's individual risers are 18 units each, under the cap, so climbing the actual staircase step-by-step is untouched — only skipping straight to a tall step from the side, or off the correct path, now requires an actual jump. Bot AI's "purposeful jump" check (Batch 6) is extended the same way, so bots don't stall at the base of terrain they now can't just walk up.

**Sundered Stair's staircase wasn't aligned with the (west) arena wall.** It sat with ~85 units of unexplained flat floor between the arena boundary and the base of the first step, reading as floating/misplaced rather than built into the level. Repositioned so the first step's near edge sits flush on `ARENA_LEFT`. Folded into the broader map-rescale pass below.

**Maps made bigger, on request, plus more maps and more/taller terrain.** The virtual coordinate space (`VIRTUAL_W`/`VIRTUAL_H`) grew from 900x500 to 1170x650 (a uniform 1.3x) — every hardcoded pixel position that assumed the old space (canvas attributes, `#game-container`'s CSS `aspect-ratio`, the P2 HUD panel's x-offset, camera position/framing distances, the directional light's shadow-camera frustum, fog near/far) was updated to match; arena-bounds-derived values (`ARENA_LEFT/RIGHT/TOP/BOTTOM`, `ARENA_CX/CY`, the floor plane, rim-edge trim, `PICKUP_SPOTS`, hazard placement) needed no changes since they were already computed from `VIRTUAL_W`/`VIRTUAL_H` rather than hardcoded. All four existing maps got a uniform 1.3x rescale of every horizontal coordinate (position/footprint) — **heights were deliberately left unscaled**, since vertical reach is governed by `JUMP_VZ`/`GRAVITY` (unchanged), not by how wide the map is; scaling both would have thrown off which platforms are jumpable. Two brand-new maps were added (**Skyreach Spire**: a three-tier platform staircase climbing to a height-200 "throne" that's flatly unreachable in a single jump from the ground — has to be climbed tier by tier, with the last gap deliberately tight for the slowest character; **The Shattered Bridge**: two ground shores connected only by a broken chain of floating stepping-stones, the center one sitting right at the edge of single-jump reach). Every existing map also picked up at least one new terrain/platform piece it didn't have before (shallow rises on Astral Proving Grounds, which previously had zero terrain; a central step on Twin Ramparts; a hard-to-reach side platform on The Colosseum Ring; Sundered Stair's fixed staircase gained a fourth tier plus a two-platform chain leading to a genuinely hard-to-reach height-160 platform, unreachable except by climbing the stair first). All six maps' spawn points and geometry (arena-bounds containment, obstacle/platform/pillar overlaps) were verified with a standalone script exercising the game's own `assertSpawnsClear()` plus additional overlap checks — not visually confirmed in a browser, since none is available here.

**Jumping had no cooldown at all — you could jump again the instant you landed.** Added `Fighter.jumpCooldown` (new `JUMP_COOLDOWN = 60` constant — noticeably longer than a jump's own ~43-frame airtime, so landing doesn't mean you can immediately jump again), ticked down alongside the existing `attackCooldown`/`dodgeCooldown` pattern and gating the jump trigger the same way. Surfaced in the `?debug=1` per-fighter state readout (`jumpCD:`) next to the existing `dodgeCD:`.

**Characters rebuilt as actual humanoid figures, on request, with attack/special animations reworked to match.** Every character used to be an abstract shape (a box/octahedron/sphere "body") with a weapon prop bolted on and animated in isolation (the prop rotating/thrusting/pulsing on its own, unconnected to any body part). New shared `buildHumanoidBase(color, opts)` builds an actual person-shaped rig — two legs, a torso, a head, and two shoulder-pivoted arms each ending in a hand socket — reused by all six character builders, which now attach their weapon(s) to a hand instead of floating them in space. `animateWeapon()` was rewritten from three prop-level animation types (rotate/thrust/pulse) down to two rig-level ones: **'swing'** rotates one arm's shoulder pivot (or an array of pivots — Voss's twin daggers stab together, Draven's two-handed hammer grip swings both shoulders in sync) through a wind-up-then-strike arc, so an attack now reads as an arm actually swinging a held weapon; **'cast'** raises the casting arm and holds it through the whole active window (rather than swinging back down mid-cast like a melee follow-through would) while flaring the held prop's scale, for the two ranged casters. Lyra keeps her ambient orbiting shard (attached to the main body, not a hand, so it doesn't fight the new arm-swing transform) alongside a second, smaller shard actually held in her casting hand; Seraphine keeps her halo the same way. Draven's old shoulder-armor pad detail was dropped rather than reworked to fit the new rig, given the scope already involved. Verified with `node --check` and the mock-DOM runtime harness (both clean); not visually confirmed in a browser, since none is available here — proportions, weapon-hand placement, and swing angles are a reasoned first pass, not a rendered/previewed result.

**Tutorial ("How to Play") added, on request.** New `#tutorial-screen` overlay, styled to match the game's existing card/panel visual language (dark slate panels, cyan accents) rather than a plain wall of text — a responsive card grid (`.tutorial-grid`, auto-fits down to one column on narrow widths) covering Objective, Movement & Jumping (including the new jump cooldown), Basic vs. Special (including how meter actually builds), Dodge, Hazards & Pickups, and a Controls card. The controls card is generated from the same `controlsSummary()` helper the pause-screen reminder already uses, so a rebind shows up correctly there too instead of a hardcoded list going stale. A prominent bordered "How to Play" button sits right under the title (separate from the muted settings-button footer, since this is the one thing a brand-new player most wants), and it auto-opens the first time the game loads in a browser — and every load after that — until the "don't show automatically" checkbox is checked, persisted via the same `safeLSGet`/`safeLSSet` helpers as the other settings. Verified with `node --check`, the mock-DOM harness, and a manual `<div>` open/close tag-balance check across the markup; not visually confirmed in a browser. **STANDING RULE going forward (user asked to remember):** every mechanic change must also update this tutorial's cards so it never drifts out of sync.

**Damage multiplied 5x, on explicit request.** Every character's basic-attack `dmg` and every special's hardcoded damage number were multiplied by 5 (Kaelen 7→35, Lyra 6→30, Gorgonok 10→50, Voss 5→25, Draven 14→70, Seraphine 5→25; specials scaled to match, e.g. Draven's Ground Breaker 45→225). Deliberately makes time-to-kill much shorter — works with the arena-collapse mechanic to force decisive fights. `STAT_MAX.dmg` (the select-screen stat-bar normalizer) was bumped so the bars still read sensibly.

**Round timer removed and replaced with Arena Collapse, on request.** There's no clock counting down to a timeout draw anymore — the whole timeout branch (`decideRoundResult(byTimeout)`, the `roundTimeLeft <= 0` path, `ROUND_TIME`/`roundTimeLeft`) is gone. Instead: new constants `SHRINK_INTERVAL`/`SHRINK_STEP`/`CRUSH_GAP`/`CRUSH_DPS` and state `shrinkTimer`/`shrinkAmount`/`playLeft`/`playRight`/`crushing`. Every `SHRINK_INTERVAL` seconds `updateArenaShrink()` pulls the playable left/right bounds inward by `SHRINK_STEP`; `clampToArena()` now reads `playLeft`/`playRight` (the shrinking bounds) instead of the fixed `ARENA_LEFT`/`RIGHT`, so fighters are physically squeezed toward center. Two glowing red wall-slab meshes (`shrinkWallLeftMesh`/`shrinkWallRightMesh`, `syncShrinkWalls()`) visualize the closing bounds. Once the gap hits `CRUSH_GAP`, the walls snap shut (`crushing = true`), input/combat freeze, and both fighters lose a **flat, equal, max/current-HP-independent** `CRUSH_DPS` per second (`hp -= CRUSH_DPS * dt/60`) until one dies — reusing the existing `hp<=0 → DEATH` flow so "whoever dies first loses" falls out of logic that already existed. `render3D` squeezes each body flat along X while crushing. The HUD's timer readout became "Walls close in Ns" / "CRUSHING!". State reset in `startRound()`. `decideRoundResult()` simplified to no longer take a `byTimeout` arg.

**Aim-lock removed, on request.** The modifier that let you move one way while facing another (`aimlock` binding, the `aimLock` local in `update()`, the `if (!aimLock) setFacing(...)` guard) is fully gone from bindings, both input branches, the controls summary, and the rebind action labels. Movement always sets facing now.

**Character models, weapons, projectiles, and attack animations overhauled + 4 new characters added, on request.** Addressed several things at once. (1) *Weapons no longer look like sticks/dots:* new prop builders (`buildSwordProp`/`buildDaggerProp`/`buildHammerProp`/`buildScytheProp`/`buildFistProp`/`buildStaffProp`/`buildWhipProp`/`buildOrbProp`) build weapons from shaped primitives — flat tapered blades with a crossguard, pommel and pointed cone tip; a bulky boxy hammer head banded on a handle; a curved multi-segment scythe hook; glowing knuckled gauntlets; a staff with a crystal head and prongs; a drooping segmented vine-whip. (2) *Projectiles look like projectiles:* `syncProjectiles()` rewritten from a plain sphere "dot" to an oriented energy bolt — an elongated crystalline core stretched along travel, a trailing cone tail, and a shimmering glow-ring halo, rotated each frame to point the way it's flying (`p.big` scales up special/overcharged bolts). (3) *The three look-alike animation pairs now differ:* `animateWeapon()` was expanded from 2 motion types to 4 (`swing` with an optional body-`twistDeg`, `stab`, `flurry`, `cast`) and re-assigned so no two similar weapons animate alike — Kaelen does a wide body-twisting horizontal cleave while Voss does a rapid in-line double `stab`; Gorgonok throws a single low-windup rising uppercut while Draven does a slow huge two-handed overhead smash; Lyra thrusts one arm forward to hurl a shard while Seraphine raises *both* arms overhead in an invocation. (4) *Four new characters:* **Nyx** (Umbral Reaper, long scythe, wide reap that yanks the enemy in; sweeps opposite Kaelen so the two blade users read differently), **Ignis** (Emberfist, dual gauntlets, rapid alternating-arm `flurry` jabs distinct from Gorgonok's single punch; fiery AOE special), **Aurelia** (Storm Herald, ranged lightning staff firing oriented bolts; a massive overcharged `big` bolt special), **Thorne** (Thorncaller, longest-reach vine-whip, overhead crack; wide bramble-lash special). Each got a full `CHARACTERS` entry, `FRAME_DATA` (basic+special S/A/R), mesh builder + `MESH_BUILDERS` registration, `doSpecial` case, `SFX_TYPE_BY_CHAR` mapping with new synthesized impact sounds (scythe/bolt/whip), and new melee-effect handling (`scythe`/`whip` added to the arc-effect branch and `effectColor` map). Select-screen support extended from 6 to 10: `P1_KEYS`/`P2_KEYS` grew to 10 entries each, `STAT_MAX` rescaled so the stat bars normalize sensibly against the new (post-5x-damage) values, and the heading key-hints were de-hardcoded. Verified with `node --check`, the mock-DOM harness, **and a dedicated standalone script that builds all 10 character meshes and runs each through a full startup→active→recovery animation cycle for both basic and special** (all 10 pass). Not visually confirmed — geometry proportions, weapon placement, animation arcs, and projectile look are reasoned first passes, unrendered. Tutorial updated with a new "The Roster" card per the standing tutorial-sync rule.

**Start screen UI overhauled, on request ("take your time on the art").** Fixed the menu-footer buttons being left-aligned instead of centered (they had a fixed width but no auto-margins — now `margin: … auto …`). The bot-difficulty selector now only shows while at least one side is set to Bot (hidden via `refreshBotUI()` otherwise). **Bot sides no longer pick a fighter by hand at all** — a side toggled to Bot swaps its fighter grid for a "Bot Fighter — randomly chosen when the match starts" card (`.fighter-bot-mode`), and its actual fighter is rolled randomly in the new `beginMatch()` at match start (hidden until then), per request. New `sideReady()` (confirmed-or-bot) + an explicit pulsing "Start Match" button that appears once both sides are ready (the start trigger for bot-vs-bot or toggle-after-confirm cases; a human confirming as the final action still auto-starts). Art pass: radial cyan/violet vignette on the overlay background, gradient panel fills with a glowing top-accent line (`.menu-section::before`) echoing the in-game neon-map trim, a larger italic glowing "VS" badge with a radial halo behind it, and a brighter pulsing Start button. Verified via `node --check`, the mock-DOM harness, and `<div>`/`<button>` tag-balance checks; visuals unconfirmed (no browser).

**Verification caught a real balance bug: a landed special instantly refilled its own meter.** Found while writing a combat-verification script (see below) that actually calls `doBasicAttack`/`doSpecial` against a live opponent instead of only checking that the mesh/animation code doesn't throw. Root cause: `takeDamage()`'s "attacker builds meter from damage dealt" logic (the Batch 4 comeback mechanic) applied to *all* damage sources, including a special's own hit — and specials deal enough damage (175-225, after the 5x pass) that `amount * METER_DEALT_RATE * meterRateMult` clamps straight back to 100 the same frame the meter was spent, for any special that connects via an omnidirectional AOE check (`distBetween`) or a melee cone that happens to be facing the target. This existed in a smaller form before the 5x damage change (a ~76% partial refill) but the 5x pass turned it into a full, instant, always-on refill — specials could chain back-to-back forever once the first one landed. Fixed by gating the attacker's own meter gain on `attacker.atkKind !== 'special'` — a special's damage still lands and still builds meter for the *defender* (the taken-damage comeback mechanic is untouched), it just no longer pays for its own recast; only basic-attack damage (plus the passive trickle) rebuilds a spent special bar now.

**New verification tooling: a live combat-exercise script**, added alongside the existing mesh/animation-only check, because that check couldn't have caught the bug above (it never calls `takeDamage`). `combatcheck.js` constructs a real `Fighter` pair per character, calls `doBasicAttack()` (confirming a melee effect or projectile is produced) and `doSpecial()` with the meter and `atkKind` set to match how `updateActionState()` actually invokes it in-game (confirming the meter is consumed), for all 10 characters. All 10 pass. This directly exercises the brief's own "every character's attack/special fires, connects, shows an effect" verification item, which no prior tooling in this file actually tested end-to-end.

**Bot AI's ranged-vs-melee detection missed the new `bolt` attack type**, found by the same pass — Aurelia (added this session, `atkType: 'bolt'`) would have played like a melee bot (walking into range, never kiting) instead of a ranged one, since `botDecide()`'s `isRanged` check only listed `'shard'`/`'orb'`. Added `'bolt'` to the check.

**Select screen's top and bottom were cut off with no way to reach them**, reported after the roster grew to 10 fighters. Root cause: `#ui-overlay` is a `justify-content: center` flex column with no overflow handling — centering content that's taller than the viewport clips *both* ends equally, and there was nothing to scroll to reach the clipped parts (the inner `.select-row` had its own `overflow-y: auto`, but that only scrolled the fighter grid itself, not the brand header above it or the settings footer below it). Fixed by switching `#ui-overlay` to `justify-content: flex-start` with `overflow-y: auto` — top-aligned and scrollable, so a taller-than-viewport select screen is fully reachable by scrolling instead of silently clipped at both edges. Removed the now-redundant nested scroll on `.select-row` (a scroll region inside a scroll region just fights the mouse wheel).

**The three footer settings buttons (Rebind Keys / HUD Text / Audio Settings) consolidated into one, on request.** New `#settings-screen` overlay (same popup pattern as the existing Rebind/Audio screens) holding all three as a vertical list; the footer now has a single "⚙ Settings" button. Rebind Keys and Audio Settings still open their own pre-existing screens unchanged (same element IDs, same handlers) — clicking either from within Settings just also closes the Settings panel first so they don't stack.

**Fighter-select grid changed from 1 column to 2, on request.** `.fighter-grid`'s `grid-template-columns: 1fr` → `1fr 1fr`. With 10 characters this also roughly halves the grid's height (5 rows instead of 10), which helps the just-fixed select-screen scroll situation above — less content to scroll through in the first place. Pure CSS change; `.fighter-btn` needed no adjustment since it already fills its container width (the global `button { width: 100% }` rule), it just now fills a half-width grid track instead of a full-width one.

## Batch 7 — Performance and memory

The floor's material is flagged `userData.keepMap = true` so `disposeObject3D`'s per-round `clearMapGroup` walk doesn't free the shared texture out from under the cache.
- [~] Pool effect meshes instead of allocating a `RingGeometry` + material per swing — **addressed via geometry sharing, not literal pooling.** `getCachedGeometry(key, factory)` caches `RingGeometry`/`BoxGeometry` shapes by their shape parameters (radius/segments/arc angle), so identical swing shapes (which is most of them — a character's basic attack always sweeps the same arc) now reuse one GPU buffer instead of allocating a new one per swing. **Batch 7 status: complete**, with two items scoped down from literal object-pooling to shared-geometry caching (see notes) — this gets the actual perf/memory win (no more per-swing/per-particle GPU buffer allocation) with far less risk than a full pool/lifecycle rewrite, which the brief's own ground rules ("don't refactor for its own sake") argue against absent a measured need for it. ## Batch 10 — Audio

- [x] Any audio at all — **fixed.** Full WebAudio synth module (no sample files, per the brief's own ground rules) — `synthTone()` (oscillator + linear-attack/exponential-decay envelope, optional pitch sweep) and `synthNoise()` (decaying filtered white noise buffer) as the two low-level primitives everything else below is built from.

- [x] Special activation stings per character — **fixed.** `sfxSpecial(f)` derives a root frequency from `hexNum(f.color) % 300` — cheap way to get six different-sounding stings (one per character's own accent color) without six hand-authored cues. - [x] Hazard warning rise → activation sound, pickup collection chime — **fixed.** `sfxHazardWarn()` (rising sawtooth) on the `dormant`→`warn` transition, `sfxHazardActive()` (low noise thump + square-wave hit) on `warn`→`active`, both in `updateHazard()`. `sfxPickup()` (two-note ascending chime) on pickup collection in `updatePickup()`.
